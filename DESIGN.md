# Griya Aleena — Design System & Creative Direction

## 1. Project Identity

**Brand:** Griya Aleena  
**Category:** Kos putri / student accommodation  
**Location:** Sekaran, Semarang, near Universitas Negeri Semarang (UNNES)  
**Primary audience:** Female university students, especially UNNES students and prospective UNNES students  
**Primary goal:** Convert visitors into prospective tenants who contact Griya Aleena through WhatsApp and arrange a room survey/visit.

### Brand positioning

Griya Aleena should feel:

- Comfortable
- Safe
- Clean
- Modern
- Warm
- Practical
- Student-friendly
- Trustworthy
- Approachable

The brand should communicate **"kos nyaman yang masuk akal untuk mahasiswa"**, not luxury accommodation and not a generic property-development company.

---

# 2. Brand Personality

The visual and written personality should be:

### Modern, but not corporate

Use contemporary web design principles without making the website look like a SaaS startup.

### Warm, but not childish

Use warmth through colour, spacing, photography, copy and subtle details rather than excessive illustrations, emojis or decorative elements.

### Trustworthy, but not bureaucratic

Information should be clear and transparent. Avoid exaggerated marketing language.

### Student-oriented, but not cheap-looking

The affordable/student-friendly positioning should come from clear pricing, useful information and practical benefits — not from a visually cheap or cluttered design.

### Local and personal

Griya Aleena is a real accommodation operated for students. The website should feel like a genuine local place where a prospective tenant can meet the owner, inspect the room and make an informed decision.

---

# 3. Primary Design Principles

Prioritise the following, in order:

1. **Clarity**
2. **Trust**
3. **Usability**
4. **Conversion**
5. **Visual personality**
6. **Decoration**

Do not sacrifice clarity or usability merely to make the interface visually impressive.

Every visual element should have a purpose.

---

# 4. Target User

The primary user is a female university student or prospective student looking for a kos near UNNES.

Typical user concerns include:

- Is the kos actually near campus?
- How much does it cost?
- Is the room comfortable?
- Is the bathroom private?
- Is there AC?
- Is WiFi available?
- Is the environment safe?
- Can I park a motorcycle?
- Can I see the room before paying?
- Is the owner trustworthy?
- Are there hidden costs?
- Is the room still available?
- How do I contact the owner?

The interface should answer these questions quickly.

Do not make users hunt through multiple sections for essential information.

---

# 5. Core Conversion

The primary conversion is:

**Website visitor → WhatsApp conversation → Room survey/visit → Rental**

The main CTA should therefore be:

**Pesan Kamar**

Secondary CTA:

**Hubungi WhatsApp**

Where appropriate, use:

**Lihat Kamar**

**Cek Ketersediaan**

**Jadwalkan Survei**

Avoid generic CTAs such as:

- Learn More
- Get Started
- Explore
- Discover
- Join Us
- Unlock
- Get Access

unless there is a specific contextual reason.

---

# 6. Important Trust Principle

Griya Aleena should explicitly communicate:

> **Jangan bayar DP sebelum survei dan bertemu pemilik.**

This is an important trust and safety message.

It should be visually noticeable but should **not** dominate the entire website.

The website should never create artificial urgency that pressures visitors to transfer money before seeing the property.

Avoid:

- Fake scarcity
- Fake countdown timers
- Fake booking notifications
- Fake visitor counters
- Fake testimonials
- Fake occupancy numbers
- Fabricated reviews
- Fabricated statistics

Only display factual availability and pricing supplied by the owner.

---

# 8. Colour Rules

Do:

- Maintain strong contrast.
- Use teal as the visual anchor.
- Use amber as an accent rather than a dominant colour.
- Allow generous white/neutral space.
- Keep the overall visual tone darker and more sophisticated than a generic pastel property website.

Do not:

- Introduce random colours without justification.
- Use rainbow gradients.
- Use excessive gradients.
- Use neon colours.
- Use purple/pink startup gradients.
- Make every section a different colour.
- Use amber for large areas simply because it is the accent colour.

---

# 9. Typography

Primary display/typeface:

**Sora**

Supporting/body typeface:

**Plus Jakarta Sans**

Typography should feel:

- Contemporary
- Clean
- Friendly
- Highly readable

Use strong hierarchy.

Recommended hierarchy:

```text
H1
↓
H2
↓
H3
↓
Body
↓
Supporting information
↓
Microcopy
```

Do not make every heading oversized.

Avoid excessive all-caps text.

All-caps may be used selectively for:

- Small labels
- Badges
- Short navigation accents

Do not use all-caps for long sentences.

---

# 10. Layout Philosophy

The layout should feel:

- Spacious
- Structured
- Calm
- Easy to scan
- Mobile-first

Use visual hierarchy rather than excessive containers.

Information should be grouped logically.

Prefer:

```text
clear section
→ clear heading
→ concise information
→ useful action
```

over:

```text
card
→ card inside card
→ card inside another card
→ excessive badges
```

---

# 11. Avoid "AI Slop" Patterns

The website must not look like a generic AI-generated landing page.

Avoid unnecessary:

- Glassmorphism
- Giant gradient blobs
- Decorative floating shapes
- Excessive rounded cards
- Excessive pill-shaped UI
- Random dashboard-style cards
- Huge statistics
- Fake social proof
- Fake testimonials
- Fake reviews
- Generic "AI startup" visual language
- Excessive shadows
- Excessive animations
- Gratuitous 3D objects
- Random abstract illustrations
- Stock illustrations that have no relationship to the property
- Overly elaborate hero sections
- Decorative text with no informational value

Do not add visual elements merely because they are trendy.

---

The hero must immediately communicate:

1. What Griya Aleena is
2. Who it is for
3. Where it is
4. Why it is worth considering
5. What the visitor should do next

Suggested positioning:

**Griya Aleena**  
Kos Putri Nyaman dekat Kampus UNNES

Supporting information may communicate:

- Starting price around Rp700 ribuan/month
- AC / Non-AC options
- Private bathroom
- WiFi
- Approximate distance/travel time to UNNES
- Early-bird or other actual offers when applicable

Primary CTA:

**Pesan Kamar**

Secondary CTA:

**Lihat Fasilitas**

The hero should not become a wall of text.

---

# 13. Photography

Photography is preferred over generic illustrations when visualising the actual property.

Prioritise real photographs of:

- Exterior
- Room
- Bathroom
- AC
- Kitchen
- Parking area
- Washing machine
- Common areas
- CCTV/security-related infrastructure
- Location/access

Real photographs increase trust.

Do not replace genuine property photography with generic stock photographs of smiling students unless there is a clear contextual reason.

Do not use a generic "beautiful woman/student" image as the main hero simply to signal that the property is for women.

---

# 14. Property Information

Important factual information should be easy to find.

Potential information hierarchy:

### Room

- AC / Non-AC
- Private bathroom
- Shower
- Sitting toilet
- Room condition
- Availability
- Price

### Utilities

- WiFi
- Free water contribution
- Washing machine
- Shared kitchen
- Refrigerator

### Security

- Fenced motorcycle parking
- CCTV 24 hours

### Location

- Near UNNES
- Approximate travel time
- Relevant access information

Do not invent specifications that have not been supplied.

---

# 15. Pricing

Price should be clear.

Current positioning:

**Mulai Rp700 ribuan/bulan**

If exact room prices differ, clearly distinguish:

- Room type
- AC / Non-AC
- Rental period
- Deposit, if applicable
- Included utilities
- Additional charges, if any

Never hide important rental conditions behind vague language.

Never manufacture a discount percentage.

---

# 16. Availability

Availability information must be factual.

If there are available rooms, show actual availability.

Do not use:

- "Only 1 left!" unless factually true
- "Almost sold out!" unless factually supported
- Artificial countdown timers
- Fake booking notifications
- Fake visitor numbers

If availability data is dynamic, make the source of truth clear.

---

# 17. WhatsApp

WhatsApp is the preferred contact channel.

The interface should make contacting the owner easy.

Use contextual WhatsApp CTAs where useful.

For example:

**Tanya Kamar Ini**

**Cek Ketersediaan**

**Jadwalkan Survei**

The CTA should ideally preserve context so the owner knows what the prospective tenant is asking about.

Do not force users through unnecessary forms before allowing them to contact the owner.

---

# 18. Mobile Design

Mobile is a primary experience, not an afterthought.

Assume many visitors will come from Instagram or WhatsApp on a smartphone.

Priorities:

- Fast loading
- Large readable text
- Comfortable tap targets
- Clear CTA
- Minimal horizontal scrolling
- Short paragraphs
- Easy image viewing
- Easy WhatsApp access
- Clear room pricing

The primary action should remain easy to reach on a mobile screen.

Avoid:

- Tiny buttons
- Dense tables
- Horizontal overflow
- Long uninterrupted text
- Desktop-first layouts
- Hover-dependent interactions

---

# 19. Navigation

Navigation should remain simple.

Potential structure:

```text
Beranda
Kamar
Fasilitas
Lokasi
Tentang
FAQ
```

Do not add navigation items merely to make the website look complete.

Every navigation item should serve a real user need.

---

# 20. Components

Use reusable components where appropriate.

Examples:

- Room card
- Facility item
- Price block
- CTA
- FAQ accordion
- Photo gallery
- Availability indicator
- Trust/safety notice
- Location information
- WhatsApp CTA

Components should have consistent:

- spacing
- typography
- border treatment
- interaction states
- button behaviour

Avoid making every section visually unique.

---

# 21. Cards

Cards are useful when they improve information organisation.

However:

**Do not turn every piece of content into a card.**

Avoid:

```text
card
card
card
card
card
```

for simple text that could be presented more naturally.

Use cards when there is a meaningful grouping or interactive relationship.

---

# 22. Border Radius

Use rounded corners selectively.

Avoid extreme rounding where every element becomes a pill.

Buttons may have moderate rounding.

Cards may have moderate rounding.

The overall visual language should feel contemporary but grounded.

---

# 23. Shadows

Use shadows sparingly.

Prefer:

- subtle elevation
- clear borders
- contrast
- spacing

over heavy shadows.

Avoid floating every element.

---

# 24. Animation & Motion

Animation should communicate hierarchy or interaction.

Good examples:

- subtle hover state
- button feedback
- smooth navigation
- gentle image transitions
- small reveal animations

Avoid:

- excessive parallax
- constant floating animations
- bouncing elements
- distracting scroll effects
- animations that slow down mobile users

Motion must never interfere with the primary conversion path.

---

# 25. Accessibility

Accessibility is part of the design, not an optional enhancement.

Ensure:

- sufficient colour contrast
- visible keyboard focus
- meaningful alt text
- semantic HTML
- usable buttons
- usable form controls
- readable font sizes
- logical heading hierarchy
- no information conveyed only through colour

Interactive elements must have clear states:

```text
default
hover
focus
active
disabled
```

Do not rely exclusively on hover.

---

# 26. Copywriting

Copy should sound like a real Indonesian accommodation business communicating with students.

Tone:

- Clear
- Friendly
- Honest
- Practical
- Warm
- Confident without exaggeration

Avoid:

- Corporate jargon
- Startup jargon
- Excessive English
- Generic AI marketing language
- Empty superlatives
- Overly dramatic claims

Avoid phrases such as:

- "Unlock your potential"
- "Experience the ultimate..."
- "Your journey starts here"
- "Elevate your lifestyle"
- "Where comfort meets..."
- "The future of..."
- "Revolutionary"
- "Game-changing"

unless there is a genuinely specific reason to use them.

---

# 27. Indonesian Language

The primary website language is **Bahasa Indonesia**.

Use natural Indonesian suitable for university students.

Avoid overly formal government-style language.

Avoid slang that may quickly become outdated.

Prefer:

> "Kos putri nyaman dekat Kampus UNNES"

over:

> "Elevate your student living experience."

---

# 28. Emojis

Use emojis sparingly.

They may be appropriate in:

- WhatsApp-oriented copy
- Social media
- Small informal accents

They should not become the primary visual language of the website.

---

# 29. Social Proof

Only use genuine social proof.

Allowed:

- Actual tenant testimonials
- Actual reviews
- Actual photographs with permission
- Actual occupancy information
- Verified facts

Not allowed:

- fabricated testimonials
- fabricated names
- fabricated reviews
- fabricated ratings
- fabricated numbers

If there is insufficient genuine social proof, simply do not manufacture it.

---

# 30. Trust & Transparency

Trust is more important than persuasion.

The website should clearly communicate:

- actual location
- actual facilities
- actual price
- actual availability
- actual rental conditions
- how to contact the owner
- how to arrange a survey

Important principle:

**Encourage prospective tenants to inspect the property and meet the owner before making a payment.**

---

# 31. Performance

Prefer lightweight solutions.

Avoid adding:

- unnecessary JavaScript libraries
- heavy animation libraries
- large image files
- unnecessary third-party trackers
- unnecessary dependencies

Optimise images.

Keep the website fast, particularly on mobile connections.

---

# 32. SEO

SEO should be natural and useful.

Potential search intent includes:

- kos putri dekat UNNES
- kos mahasiswa UNNES
- kos putri Sekaran
- kos dekat Kampus UNNES
- kos murah dekat UNNES
- kos putri kamar mandi dalam dekat UNNES

Do not keyword-stuff.

Write for users first.

---

# 33. Technical Design Constraint

When modifying an existing implementation:

1. Preserve existing functionality unless explicitly asked to change it.
2. Inspect the existing implementation before changing it.
3. Reuse existing components and styles where practical.
4. Avoid unnecessary rewrites.
5. Do not introduce a framework merely for cosmetic reasons.
6. Do not change APIs or data structures unless required.
7. Do not remove working functionality without explicit instruction.
8. Keep mobile behaviour in mind for every UI change.
9. Test the affected interaction after making changes.

---

# 34. Content Accuracy

Never invent factual information.

If information is missing, use a neutral placeholder or ask for the information.

Do not fabricate:

- room dimensions
- distance
- prices
- discounts
- testimonials
- tenant counts
- occupancy rates
- facilities
- security features
- transport times
- reviews
- awards
- certifications

---

# 35. AI Anti-Slop Rule

When the project includes `antislop.md`, treat it as an additional quality filter.

Use:

```text
DESIGN.md
+
antislop.md
+
user instructions
```

as the design context.

`DESIGN.md` defines **what Griya Aleena should feel and look like**.

`antislop.md` defines **patterns that should generally be avoided**.

The user's explicit project requirements take precedence over generic stylistic preferences.

Do not blindly apply Anti-Slop rules if doing so would conflict with an explicit functional requirement.

---

# 36. Decision Rule for New Design Elements

Before introducing a new visual element, ask:

1. Does it improve understanding?
2. Does it improve trust?
3. Does it improve usability?
4. Does it improve conversion?
5. Does it reinforce Griya Aleena's identity?
6. Is it necessary?

If the answer to all is no, do not add it.

# 38. Final Creative Direction

The final impression should be:

> **"Ini kos yang benar-benar ada, dekat UNNES, nyaman, aman, transparan, dan dikelola secara serius — tetapi tetap terasa dekat dengan mahasiswa."**

It should NOT feel like:

> "AI-generated startup landing page."

When there is a choice between a flashy design and a clear, trustworthy design, prefer the clear and trustworthy solution.

When there is a choice between adding another visual element and improving information hierarchy, improve the information hierarchy.

When there is a choice between persuasive exaggeration and transparent factual communication, choose transparency.
